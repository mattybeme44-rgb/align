The iPhone microphone needs no interface: pick it and the generated reference is used — the exact noise the app plays. Be clear about what that measures. The curve is the phone's own chain: its speaker, the room between them and its microphone, not your system. Expect little energy below roughly 300 Hz, a direct path through the phone's own body, a delay dominated by the phone's audio latency, and the speaker's own voicing. Use it to learn the workflow and to compare two captures taken the same way — not for absolute response, sub alignment or distance.

A USB-C interface reopens the stream when chosen. Output over Bluetooth adds 100–300 ms of wandering latency, so use a cable or an interface to measure.

Reference

Generated compares the microphone with the noise or sweep the app plays, so one input is enough. Loopback takes the reference from input 2 of the same interface — the true dual-channel method. Both channels must come from that one device on one clock: a phone microphone and an interface run on separate clocks, drift apart and turn a coherent measurement into noise, so they cannot be paired.

How this measures

Two signals are compared sample by sample: a reference and a measurement. In Generated mode the reference is the exact noise or sweep this app plays, so a single microphone is enough. In Loopback mode the reference is whatever arrives on input 2, which is the true dual-channel method.

The averaged cross spectrum gives the transfer function — magnitude, phase and coherence — and its inverse transform is the impulse response, whose peak is the delay. Delay compensation removes that delay from the phase so two systems can be compared for alignment.

Levels read dBFS by default. A calibrated measurement microphone comes with a sensitivity figure, and entering that offset turns the input readout into dB SPL. Measurements stay relative either way, which is what alignment work needs.
